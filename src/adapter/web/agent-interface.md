# Agent 聊天接口

WebSocket 每帧为一个 JSON 对象，正文使用纯文本。前端读取 `/agent-config.json` 的 `url` 决定连接目标，空字符串表示不连接任何后端。配置修改后刷新页面生效。

## 最小接入

1. 后端接受配置地址上的 WebSocket 连接。
2. 接收 `hello` 握手和 `msg` 用户消息。
3. 返回 `msg` 助手消息。

连接建立后前端默认显示在线。后端暂不可处理消息时，可发送 `presence` 将其设为离线；恢复后发送在线状态。WebSocket 断开时前端禁用发送，并以 1 秒起、最多 10 秒的间隔自动重连，每次重连都会发送 `hello`。

## 前端发送

建立连接：

```json
{"type":"hello","name":"你"}
```

发送用户消息：

```json
{"type":"msg","id":"客户端生成的 UUID","text":"你好"}
```

`id` 标识这条用户消息。前端在成功写入连接后立即显示用户消息；后端无需回显。若后端回显或在历史中回放这条消息，必须保留原 `id`，以避免重复显示。写入连接不等于后端已持久保存；前端不会自动重发断线时未确认的消息。

## 后端发送

助手回复：

```json
{"type":"msg","id":"服务端生成的唯一消息 ID","role":"assistant","text":"你好！","ts":"2026-10-08T06:00:00.000Z"}
```

用户消息回显（可选）：

```json
{"type":"msg","id":"原客户端 UUID","role":"user","text":"你好","ts":"2026-10-08T06:00:00.000Z"}
```

`role` 为 `user` 或 `assistant`，决定气泡方向；角色显示名称与头像由前端管理。`text` 为非空字符串，原样显示，不删改 agent 的回复。`id` 建议为每条消息提供唯一且稳定的值，重连回放时保持不变。`ts` 为 ISO 时间字符串，省略时使用接收时间。

为兼容已有的消息信封，也接受省略 `role`、提供 `from` 的消息：`from` 等于握手名称时视为用户，其他名称视为助手。新后端应使用 `role`，不依赖显示名称判断角色。

历史回放（可选，在 `hello` 后发送，按时间从早到晚排列）：

```json
{"type":"history","messages":[{"id":"history-1","role":"user","text":"之前的问题","ts":"2026-10-08T05:59:00.000Z"},{"id":"history-2","role":"assistant","text":"之前的回答","ts":"2026-10-08T05:59:01.000Z"}]}
```

也支持逐条 `msg` 携带 `"history":true`。有 ID 时按 ID 去重；没有 ID 的历史消息按角色、正文和时间去重。前端只保留当前页面已显示的消息，不负责持久保存历史；刷新页面后由新后端重新提供。

可用状态（可选）：

```json
{"type":"presence","online":false}
```

输入状态（可选）：

```json
{"type":"typing","active":true}
```

前端发送消息后默认显示「正在输入」，收到新的助手消息、离线状态或错误后停止；后端也可以用 `active:false` 主动停止。

请求错误（可选）：

```json
{"type":"error","text":"本次回复失败，请重试。"}
```

错误显示在输入框下方并停止输入动画，连接保持可用。服务不可用时另发 `presence` 或关闭连接。无效 JSON、未知类型和格式错误的消息会被忽略。

当前接口支持纯文本完整消息；图片、工具面板与逐字增量显示需要在后续扩展协议和 UI 时实现。
