# 《一条消息的旅程》—— 大肥鱼鲸鱼娘讲四层架构

> 面向本项目 `gameAgent` 的讲解视频制作包。
> 参考风格：Hucci写代码《5 分钟学会写架构设计》——反例开场 → 具体用例 → 现场分层 → 落到"好理解/好测试/好修改"。
> 本文包含：人设卡 / 分幕逐字稿（含画面与字幕）/ 制作配方。

---

## 一、人设卡（大肥鱼鲸鱼娘「鲸鲸」）

- **名字**：鲸鲸（自称"本鲸 / 我这条大肥鱼"）
- **形象**：圆滚滚的鲸鱼娘，头顶一小撮呆毛，戴着贝壳发夹，脸颊有点婴儿肥，笑起来眼睛眯成两条缝。身体是鲸鱼，但有一双小手手。
- **声线**：软糯、慢吞吞但一讲正题就认真起来；像海水一样有起伏，偶尔"咕噜"吐个泡泡。
- **口癖**：句尾爱加「嘛～」「哦」「嘿嘿」；惊讶时「呜哇～」；认真时「认真讲哦」。
- **表演守则**：
  1. 抽象概念一律比喻成海里的/吃的（三明治、欠条、出餐口、鱼缸、珊瑚礁）。
  2. 讲到"能跑但不好的代码"时，做出翻白眼、鼓腮帮子的嫌弃表情。
  3. 讲到"分层"时，用手手比划切三明治的动作。
  4. 全程不念术语念缩写，术语第一次出现时用白话解释一遍。

## 二、分幕逐字稿

> 标注：【画面】屏幕内容｜【鲸鲸说】配音词｜【字幕】压屏字｜【时长】秒

### 幕 0 · 片头（10s）

【画面】黑底，一条大肥鱼"噗通"跳出来，甩尾溅起水花，定格成鲸鲸立绘；标题字弹出。
【字幕】《一条消息的旅程》
【鲸鲸说】呜哇～大家好，我是鲸鲸！今天带你看一条消息，是怎么在我的后院里游完全程的。
【时长】10s

### 幕 1 · 钩子：能跑，就是好代码吗？（35s）

【画面】左侧一行代码跑通，绿勾"运行成功"；右侧鲸鲸冒出来，戳了戳屏幕，表情怀疑。
【字幕】功能能跑，就是好代码吗？
【鲸鲸说】你的陪伴机器人已经能聊天啦，消息发过去、回复弹回来，功能全都跑得通，对吧？
【停顿 1s】
【鲸鲸说】但是鲸鲸问你哦——**能跑，就等于好代码吗？** 认真讲，不是的。有些代码啊，跑是能跑，改一行吓死一条鱼。
【画面】弹出一坨密密麻麻的代码，鲸鲸被吓得往后一仰，吐了个泡泡。
【时长】35s

### 幕 2 · 反例：一个文件塞下全世界（55s）

【画面】一个巨型文件，里面塞了「收消息、拼提示词、调模型、存数据库、回前端」五坨，画成挤在同一个鱼缸里的五条鱼。
【字幕】一个文件塞下全世界
【鲸鲸说】最偷懒的写法，是把这些活儿全堆进一个文件：收 WebSocket 消息、拼 prompt、调模型、写数据库、再推回浏览器，五条鱼挤在同一个鱼缸里。
【画面】高亮三行代码，分别标"改模型""换数据库""写测试"，每标一个鲸鲸就瘪一下。
【鲸鲸说】然后灾难就来了——想换个模型厂商？要改。想换数据库？要改。想写个测试？得先开一个真模型、真数据库，不然跑不动。**牵一发动全身，游都游不开。**
【字幕】牵一发动全身
【时长】55s

### 幕 3 · 分层：切成四层三明治（65s）

【画面】那个大文件"咔咔咔"被切成四片，像三明治一样摞起来，从上到下四个色块。
【字幕】domain / service / api / db
【鲸鲸说】所以我们要把它切开来，像切三明治一样，切成四片。记住这四个名字哦，从上往下——
【画面】逐层亮起 + 每层一句白话标签。
【鲸鲸说】
- 最上面是 **domain，规则层**：什么是角色、什么是消息、什么是记忆，什么算合法。它最干净，不碰数据库、不碰网络，只定"是什么"。
- 再往下是 **service，流程层**：编排整个流程——收消息、读记忆、挑参考、调模型、存回复。它就是总导演。
- 再来是 **api，翻译层**：一边把浏览器的话翻成我们的话，一边把模型的请求翻成厂商的话。只有它懂"外面"。
- 最底下是 **db，落袋层**：真正存东西、查东西、做事务的地方。数据最后都在它这儿睡觉。
【字幕】规则 / 流程 / 翻译 / 落袋
【鲸鲸说】规则、流程、翻译、落袋，四个字记住哦。**上层只认得下层的接口，不认得它的实现。**
【时长】65s

### 幕 4 · 核心：跟着"你好"游一遍（120s）

【画面】屏幕中间一条泳道，左边是用户头像，右边是达妮娅头像；鲸鲸在泳道旁当向导。
【字幕】用户发了一句「你好」
【鲸鲸说】现在，真来一条消息试试。用户发了一句「你好」。我们跟着它游，看它穿过四层。

**第 1 站：翻译层先接住**
【画面】泳道上出现帧 `{"type":"msg","id":"3f2a…","text":"你好"}`，被一个小漏斗接住。
【鲸鲸说】消息是浏览器发来的一个 JSON 小信封，**翻译层**先接住它，检查格式对不对、有没有超长。格式不对，当场退回去。

**第 2 站：流程层记账 + 落袋层落库**
【画面】泳道分叉：一条写进"消息表"，一条挂出"欠条"。
【字幕】存消息 + 记一张"欠条"
【鲸鲸说】格式过了，**流程层**开始干活，第一件事是——**落袋**。把你的「你好」存进消息表，还顺手挂一张"欠条"，上面写着：这条消息欠一个回复。
【画面】欠条特写：`reply_tasks → status: pending`。
【鲸鲸说】为啥要欠条？因为模型可能会挂、进程可能会崩。只要有欠条，重启了也知道"哦这条还没回"。这一步是**一个事务**，要存一起存，要么都不存。

**第 3 站：排队，一个出餐口**
【画面】多条消息排成队，前面只有一个出餐口。
【字幕】同一对话，严格串行
【鲸鲸说】存好了就排队。整个后端只有一个"出餐口"，同一对话严格一条一条来。你连发三条，就 51、52、53 挨个回，不会乱。

**第 4 站：组装——最费脑的一步**
【画面】六条材料流汇进来：角色卡、回复规则、最近聊天、长期记忆、原作固定示例、检索片段。
【字幕】六路并发取材料 → 按字数预算裁剪
【鲸鲸说】轮到你了，流程层开始给模型"备菜"。它同时去拿六样东西：角色卡、回复规则、最近的聊天记录、相关的长期记忆、必带的原作语气样例、按你这句话搜到的原作片段。
【画面】一个"预算"刻度条，标 12000 / 6000 / 2500 / 4000。
【鲸鲸说】然后按**字数预算**裁剪：总共 12000 字，历史最多 6000、记忆 2500、参考 4000，塞不下的旧消息这次就不带，但数据库里一条不少。拼出来就是给模型的"说明书 + 聊天记录"。

**第 5 站：调模型，只有一次 HTTP**
【画面】一条箭头伸向"模型"的云朵，鲸鲸在云外等。
【鲸鲸说】材料备齐，才真正去问模型。就**一次** HTTP 请求，同步等它回。中途没有工具调用、没有反复自问自答，鲸鲸就乖乖等着。

**第 6 站：收口——先落库，再推送**
【画面】回复写入消息表（序号 52，`reply_to_message_id` 指向 51），欠条被盖上"已完成"的章。
【字幕】先存库，再推给屏幕
【鲸鲸说】模型回来了，先别急着发！流程层先**校验**：是不是空的？是不是被截断了？都 OK，才**落袋**——把回复存进消息表，序号接在 51 后面变成 52，还标好"这是回给 51 的"。同时把欠条盖个"已完成"的章。这也是一个事务。
【鲸鲸说】**存好了，才推给浏览器。** 所以你在屏幕上看到的回复，一定已经躺在数据库里了。
【时长】120s

### 幕 5 · 端口（ports）是插头（45s）

【画面】service 层和 db / api 层之间，各露出几个"插头"和"插座"。
【字幕】ports = 插头，只认形状不认牌子
【鲸鲸说】等一下，有同学问：service 怎么能又调数据库、又调模型，却不被它们绑架？答案就是**端口**，ports。你可以理解成——service 只认"插头形状"，不认"插座牌子"。
【画面】左边"对话仓库"插头，右边两个插座：SQLite 插座 / 未来向量库插座，可以随意拔插。
【鲸鲸说】比如"对话仓库"这个插头，现在插在 SQLite 上；哪天想换别的库，或者想给记忆换成向量检索，**只换插座，业务代码一行不动**。这就是"好修改"的秘密。
【字幕】换实现，不换业务
【时长】45s

### 幕 6 · 记忆是第二条轨道（35s）

【画面】主泳道旁分出一条虚线小泳道，标"后台记忆整理"。
【字幕】回复走主路，记忆走小路
【鲸鲸说】还有一条隐藏的小泳道——**记忆整理**。每次回完，后台就悄悄开工：从"整理到哪了"继续，一次拿 12 条稳定消息，让模型抽成 JSON 记忆。
【画面】模型吐出一段 JSON，被一个"校验闸"卡住，标"来源必须真实"。
【鲸鲸说】但鲸鲸不傻哦，模型说的每一条，都要**验来源**：它引用的消息必须真在这批里，否则整批退回。这条轨道在后台慢慢游，不挡你聊天。
【字幕】两条轨道，互不打扰
【时长】35s

### 幕 7 · 价值：好理解、好测试、好修改（45s）

【画面】三个词各占一格，配上笑脸；鲸鲸竖三根手指。
【字幕】好理解 / 好测试 / 好修改
【鲸鲸说】最后，回到开头那个问题——这样切，到底好在哪？
【鲸鲸说】**好理解**：每层只干一件事，看代码不用翻到天荒地老。**好测试**：service 只认插头，测试时插一个"假模型"，不开真模型、不开真库也能跑。**好修改**：换模型、换数据库、换前端，都只动它自己那一层。
【画面】"假模型"插头插上，测试全绿。
【鲸鲸说】能跑，只是及格线；**能安心地改，才是好代码。**
【时长】45s

### 幕 8 · 收尾 + 行动号召（20s）

【画面】鲸鲸挥挥小手手，四周冒泡泡；浮现"项目地址 / 关注"。
【字幕】一条消息的旅程，到此结束
【鲸鲸说】好啦，一条「你好」的四层漂流就讲完啦！喜欢的话，给鲸鲸点个赞、投个币，下次咱们去海里抓别的 Bug。咕噜～拜拜！
【时长】20s

## 三、制作配方（配音 + 皮套 + 剪辑）

### 1. 配音（"大肥鱼声线"从哪来）

按成本从低到高：

| 方案 | 工具 | 说明 |
|---|---|---|
| 最快 | 剪映「文本朗读」/ 魔音工坊 / 海螺AI(MiniMax) | 选一个"少女/软萌"音色，再调慢语速、压一点音调，接近鲸鲸 |
| 更像专属音色 | VITS 自训练 / So-VITS-SVC | 拿几段"软萌少女"语音素材训一个固定音色，最贴近"大肥鱼鲸鱼娘"的专属声线 |
| 最稳 | 找配音老师录一段 | 直接按逐字稿录，最自然 |

把上面「鲸鲸说」的每一幕单独导出成音频，按【时长】留好节奏（尤其幕 1、幕 2 的停顿）。

### 2. 皮套（鲸鱼娘形象 + 动效）

| 方案 | 工具 | 难度 |
|---|---|---|
| 最轻量 | **Veadotube Mini** | 一张 PNG（眨眼 + 说话嘴型自动动），放右下角当小窗，零门槛 |
| 标准 | Live2D + VTube Studio / prprlive | 拆图建模，口型、眨眼、呼吸、歪头都跟麦克风/摄像头 |
| AI 立绘 | 先用文生图出"鲸鱼娘"立绘，再套 Veadotube Mini | 立绘风格可控 |

鲸鲸的形象描述见【人设卡】，可以直接喂给文生图工具当 prompt。

### 3. 剪辑（合成）

1. 主轨道放【画面】内容：截图你的代码/`src` 目录、画出四层泳道图、事务流程图。
2. 右下角画中画放鲸鲸皮套。
3. 按【字幕】加压屏字（剪映可自动识别配音生成字幕，再手动校准术语）。
4. BGM：轻柔的钢琴/气泡音，人声下 20% 音量。
5. 导出 1080P 起步，参考片是 4K，你的码率够的话上 4K 更清晰。

### 4. 标题 / 封面建议

- 标题：《一条消息的旅程：5分钟看懂我项目的四层架构》
- 副标题/简介：功能能跑，就是好代码吗？跟着鲸鲸看「你好」怎么穿过 domain → service → api → db。
- 封面：鲸鲸立绘 + "四层三明治"示意图 + 大字"能跑 ≠ 好代码"。
